How RAG works

Explore each stage, then ask a question to see the retrieval pipeline in action.

1

Collect source documents ✓

Start with useful material: PDFs, webpages, FAQs, manuals, or notes.

📕PDF guide
🌐Website
📝FAQ text
2

Split into chunks ✓

Break long documents into smaller text passages that can be retrieved individually.

Chunk AThe Eiffel Tower is in Paris…
Chunk BIt was completed in 1889…
Chunk CThe tower is about 330 metres…
3

Create embeddings ✓

An embedding model maps each chunk to numbers that capture aspects of its meaning.

“The Eiffel Tower is in Paris” → [0.12, −0.34, 0.56, …]

Important: the chunk is text; the embedding is its numerical representation.

4

Build the knowledge base ✓

Store vectors with the original text and metadata in a vector database or searchable index.

🛢️
Vector databaseEmbedding + chunk text + source reference
5

Process the user's query ✓

The query is usually embedded too, so the system can search for semantically similar content.

“Where is the Eiffel Tower?” → query embedding → search
6

Retrieve and optionally rerank ✓

Retrieval gathers candidates. A reranker can reorder them by query relevance, then the top chunks are selected.

Chunk A · initial retrieval0.87
Chunk B · initial retrieval0.92
Chunk C · initial retrieval0.81
7

Generate an answer with the LLM ✓

The LLM receives the question plus the selected text as context and composes an answer.

Question＋Top chunks→LLM ✨→ Answer
8

Return the response ✓

The user receives the answer, ideally with source citations so they can check the evidence.
